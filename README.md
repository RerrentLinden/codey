# Codey

Codey 是 Codex 桌面客户端的增强启动器。打开 Codey 后，它会自动拉起 Codex，并在 Codex 页面内提供统一的 Codey 控制台，用来管理线路、模型、会话、通知、插件、更新和运行策略。

## 功能描述

- 持续检查 Codey 是否仍能响应；发生异常或连接中断时，Codex 页面右上角的 Codey 图标会显示醒目的异常标识和处理提示。关闭由 Codey 启动的 Codex 后，Codey 也会同步退出。
- 自动启动 Codex，并在页面顶部提供 Codey 控制台入口；可查看运行状态、Codex 版本和应用路径，重启由 Codey 启动的 Codex，并通过控制台顶部的“问题反馈群”入口扫码加入反馈群；还可检查、下载和安装 Codey 更新。打开 Codey 时会先检查更新，等待较久时显示系统提示，最多检查 10 秒；更新源不可用时会自动跳过，发现可安装的新版本时会先询问是否更新。选择稍后会正常进入 Codex，并在 Codey 图标显示更新红点。
- 管理官方登录线路与第三方线路。首次使用时只会自动带入当前可用线路一次；之后第三方线路使用 Codey 保存的数据。每次启动若检测到 Codex 正在使用官方账号登录，会把官方直登作为第一条可用线路；从第三方 API 启动时需先在 Codex 完成官方登录并重启 Codey，才可新增或启用官方线路。所有第三方线路会同时接入一个本地路由，不需要先切换或启用某条线路；对话中选择模型后，本地路由会按模型所属线路自动分发请求。控制台以左右等宽方式展示线路和模型：左侧线路卡片只用于新增、编辑和删除配置，右侧聚合全部供应商模型并按线路分组，可直接设置每条线路的默认模型。官方账号编辑弹窗可选择支持的模型并控制是否在账户区域显示额度，开启后线路卡片会显示状态；第三方模型可同步或手动维护，删除线路后对应模型会立即移除。
- 线路信息兼容手工配置以及 CC Switch、Code Switch R 已写入 Codex 的当前线路。Codey 只读取用户已有的 Codex 线路配置，不会修改、迁移或重写它；第三方线路会通过本次启动内的 Codey 本地线路入口接入，官方直登仍保留官方账号通道。新增线路、修改接口地址或认证信息后会尽量即时生效；完成加载后，在不同线路的模型之间切换无需重启。
- 在官方账号线路下把周额度和可用的 5 小时额度整合到账户区域，以标签显示当前套餐，并展示剩余比例与重置时间；鼠标悬浮时可查看各周期用量、Credits 余额和更新时间，也可在控制台关闭。
- 可为任意第三方线路同步可用模型、设置默认模型并维护自定义模型；模型较多时可搜索并分批浏览。Windows 已信任的内网证书和线路已有的额外鉴权设置也会用于模型同步。CC Switch 路由开启时会从其当前源 API 获取模型列表，不会把路由占位凭据发送给源服务。首次使用时也可直接保存手动输入的模型。第三方线路中的所有模型都只通过该线路调用，即使模型名称与官方模型相同，也不会切换到官方账号通道。保存后会尽量立即刷新 Codex 的模型选择器，失败时按界面提示重启生效。
- 增强会话管理：显示更友好的会话时间，运行中的任务会在各自列表内稳定地优先显示；展开项目时，藏在首批会话之后的运行任务也会自动补充显示并置顶，短暂状态切换时不会立即闪回；其余任务沿用官方的置顶、优先级、最近更新与手动排序，支持导出、导入、删除指定轮次、恢复最近备份；启动时会先确认当前线路完整有效，线路切换尚未完成时驻留等待恢复而不会反复退出，再按稳定线路修复历史会话归属，并提升历史会话恢复到原项目的稳定性。使用仅在 Codey 中保存的第三方线路，不会让历史会话在原版 Codex 中因线路缺失而无法打开；旧版本造成的异常会在下次安全启动时自动修复。
- 增强插件市场与页面体验：修复官方和本地插件展示，支持一键检查并尝试修复插件市场，保存个性化页面增强设置，并可按需屏蔽完全访问模式下反复出现的安全提示（默认关闭）。
- 提供启动与平台体验优化：减少 Codex 卡在启动页的情况；长时间运行时会自动收敛重复遗留的 MCP 与临时执行进程，避免每次工具调用后进程数和内存持续累积，正常的持久工具连接不受影响；Windows 会限制异常密集的后台 Git 状态与审查请求，降低大量短时 Git 进程造成系统资源耗尽的风险，同时阻止 Codex 异常的周期性 WMI 进程采样。保护状态会在启动时完成一次完整自检；自检通过后即显示为已生效，实际拦截次数另行展示，不会为了确认状态持续检测。系统优化详情只列出已经生效的用户功能，当前运行中的内置或已有 FastCtx、子代理优化、正在监听的通知渠道，以及实际生效的 Trace 与 Crashpad 磁盘保护也会在这里汇总；新的生效功能会自动加入列表，渲染器控制等内部基础组件不会混入功能数量，Windows 专属保护也不会在 macOS 中显示为生效。还可选择 Codex 安装目录、显示首次启动失败提示，并提供渲染启动策略用于排查显示异常。
- 支持按需精简宠物功能：默认收起宠物、隐藏宠物入口，并避免在启动时预先创建隐藏的宠物窗口；主动使用官方语音功能时仍可按需启用共用能力，关闭精简后可恢复完整宠物体验。
- 支持上下文工具增强，改善长任务中的文件读取、搜索和替换体验；开启后会批量读取已知文件、先缩小搜索范围并控制结果规模，减少重复调用和不必要的 token 消耗。普通文件读取、文本搜索和文件发现会优先使用 FastCtx，带特殊格式、统计、流式或高级搜索语义的终端命令仍会直接执行，构建、测试、Git 等任务不受影响；工具不可用或失败时可安全回退。共享服务连接意外中断时会自动恢复后续调用，运行中的替换不会被重复执行。内置工具来自 [yc-duan/fastctx](https://github.com/yc-duan/fastctx)；当前 `glob` 更偏向忽略规则，必要时可以显式排除不想看的路径。检测到已经配置自己的 FastCtx，或暂时无法确认其状态时，Codey 会禁用内置工具开关并说明原因，避免重复加载；通过 Codey 启动后，旧版工具提示也会完成一次性迁移，不会在退出时重新出现。CC Switch 路由开启期间，线路切换只更新线路，不会覆盖这套工具规则。
- 支持提示词优化：可单独配置提供 Responses API 的接口，也可在第三方线路下同步当前线路的地址、密钥和默认模型。默认优化指令会直接显示在输入框中，可按需微调，并可随时测试接口连通性。启用后，Codex 输入框旁会出现「优化」按钮，优化结果会替换原内容并保留在输入框中供继续编辑；配置变更即时生效，API Key 不会显示在页面中。
- 基于 Codex 原生子代理提供 Codey 角色与调度增强；开启后，单一事实、已知位置修改和顺序任务仍由主代理直接完成；需要多点独立检索、归纳多个候选文件或处理两个独立分支时，会更积极使用只读子代理，较重的独立实现和专门视觉取证也会按任务类型委派。任务规模只作为调度参考，不会因为调用数或文件数估算偏小而被硬性拦截；写入型子代理仍保持较高门槛。已确认的纯只读任务默认最多同时使用三个子代理；批次包含写入型或身份未确认的代理时，最多同时使用两个。每次派生仍会提前检查并行任务的读写范围；上一批完全收拢后，主代理会明确选择继续下一批、转为自己处理、完成任务或报告阻塞；如仍有合适的独立工作，可在同一次回复中继续，不必等待下一条消息。这些协作控制不会扩大其他工具的使用范围；若它们持续不可用，门禁会在有限次数后保守结束本轮并禁止继续派生，而不是反复卡住。派发批次和累计尝试次数不再设置固定预算上限；并发槽释放并完成批次决策后可以在同一次回复中继续，适配长期 Goal 任务。上游隐藏任务正文时，保守兼容模式只派发只读任务；需要写入时会交回主代理，或要求使用可验证的任务契约。正文可见时写入任务仍由主代理原样复跑约定检查，成功才会标记为通过。检查连续失败或长时间无法取得可信结果时，会明确标记为“未验证”并有界释放，不会无限卡住任务，也不会伪装成通过；检测到子代理状态载荷缺少关键字段或结构变化时，也会显示兼容性诊断并要求对账。编排账本保留的兼容计数只用于诊断，不会阻断派发，也不代表实际 token 账单。可分别为“快速定位、深度检索、视觉分析、代码实施、视觉实施”五类专用任务选择当前线路可用的模型和思考深度，包括新版 Codex 支持的轻量子代理模型与第三方模型；保存后下一次派生直接生效。角色的只读或可写设置是默认工作方式，实际权限仍受父任务当前权限模式约束，不会因开启增强而扩大。在完成身份与角色校验后，Codey 不再按任务中声明的目录限制实际读写；子代理能否访问其他工作树或目录，以父任务的 Codex 权限设置为准。首次开启或关闭仍按界面提示重启。切换线路后会尽量保留每一类的原选择，模型确实不可用时再回退；CC Switch 路由切线不会覆盖协作规则。子代理不能继续向下派生；主代理会先派完同一批独立任务再等待，局部更新不会被误当成完成，异常代理会先核对并停止，再由主代理接管未完成部分。仍在运行的任务全部只是已确认的只读检索时，主代理可以在等待间隙继续查看和搜索本地文件，先处理已经返回的结果；写入、命令、联网和结束任务仍会等待全部收拢，存在写入、命令或身份未确认的代理时也继续保持原有等待保护。仍在运行的代理可以接收必要补充；已经结束或属于上一轮的代理不会被重新唤醒执行新写入，系统会在唤醒前立即提示改用新任务或由主代理接管，避免运行很久后才在首次修改时失败。正常完成、限流或服务异常都会按对应终态收拢；异常初始化或协作工具意外不可用时，等待保护也会有界释放。用户在代理运行中追加、改变或取消要求时，系统会先重新核对状态；只有被明确取消的子任务会停止，状态询问或补充信息不会误停其他代理。已经完成的结果不会因稍晚到达的停止请求被误记为丢失，被取消请求的迟到结果也不会继续驱动新工作；Codex 异常退出后再次启动时，只恢复尚未完成的写入验收，不沿用已失效的只读任务或等待锁。
- 当协作线路会隐藏写入任务正文时，Codey 会先在同一轮中独立登记本次写入的明确工作区根范围和完成检查，再允许对应的写入型子代理启动；登记只能使用一次，过期、跨轮次、跨批次、范围发生变化或信息不一致都会拒绝。这样既能恢复代码实施和视觉实施角色的正常派发，也不会因为看不到任务正文而默认扩大写入权限。
- 只读子代理可直接使用受信任的网页搜索和页面读取能力，不必改用写入型角色或额外声明网络权限；实际联网范围仍以 Codex 当前权限设置为准。需要审查 Git 状态、提交或差异时，只读子代理也可按任务声明运行终端命令，不必伪装成写入型角色；命令能力本身不会开放文件写入，实际副作用仍受角色配置和 Codex 当前权限模式约束。
- 子代理的模型和思考深度会按线路分别记住；首次进入新线路时沿用上一线路的选择，模型不受支持时才为新线路回退，切回原线路会恢复原来的配置。第三方线路中明确保存的模型始终按该线路模型处理，不会因为名称与官方模型相同而改走官方账号；线路模型列表暂时遗漏时不会擅自改掉角色，但该选择本身不代表供应商已验证可用。每次启动以及在增强已启用时保存设置，都会核对 Codey 实际交给子代理的完整角色配置；发现任意陈旧、缺失或损坏内容时按当前角色矩阵自动重建，不依赖具体模型名称，也不会改动用户自己的角色文件。新派生的子代理在首次使用工具前还会核对实际加载的模型和思考深度；无法证明或与角色选择不一致时会暂停该子代理，而不是让它在错误映射上继续工作。
- 当子代理状态载荷只缺少单个标识、但仍能确认调用来源时，主代理不会再在首个子代理启动后误锁住同批后续派发；来源无法确认时仍会保守暂停并提示对账，子代理继续向下派生仍会被拒绝。若模型误用已经派发过的任务名称，系统会先核对原代理并继续等待或交回主代理，不会把去重拒绝误当成任务完成后直接结束。
- 打开包含历史子代理的任务时，会校准少量仍误显示为运行中的可疑状态，无需再进入详情页并返回；校准只核对必要的最新状态，不扫描完整历史。
- Codey 自带的协作与上下文规则会与用户规则分开保存；升级只替换仍保持默认内容的旧版规则，用户修改过的内容会原样保留，避免重复安装造成规则叠加。
- 提供统一的诊断存储统计、清理和保护：可阻止 Trace 日志持续写盘，并在 macOS 上限制待处理崩溃报告异常堆积，帮助避免诊断数据长期占用磁盘。
- 支持最多 32 个飞书机器人（包括企业内网部署）、企业微信 Webhook 和 Telegram 通知渠道，可单独启停、删除和测试；测试通过后保存会立即生效，并在任务完成、失败或等待介入时发送提醒。安装 Codey 更新前会先保存尚未落盘的设置，避免更新重启后丢失。

## 使用方式

打开 Codey 后，它会自动启动 Codex。进入 Codex 后，点击顶部的 “Codey” 按钮即可打开控制台。已加载线路之间的模型切换会立即生效；多数线路新增、删除和模型选择变更也会即时刷新，其他需要重启的设置请按界面提示保存并重启 Codex。

## 注意事项

- Codey 面向 Codex 桌面客户端，不覆盖命令行版本。
- Codey 已移除协议转换能力，只支持 Codex 原生可用的 Responses API。需要连接其他对话协议时，请自行部署第三方网关或路由软件完成转换。
- 第三方线路是否可用取决于对应服务本身的能力与账号配置。
- 从第三方 API 启动时不能新增或启用官方账号线路；需要官方模型时，请先在 Codex 完成官方账号登录，再重新启动 Codey。
- 保留官方账号登录只保留 Codex 的账号状态，不会把已选择的第三方线路切回官方接口。
- 删除、导入和恢复类会话操作会尽量保留备份，但仍建议谨慎使用。
- Windows 和 macOS 上启动 Codey 时，如果 Codex 已在运行，Codey 会先将其关闭再重新启动；正在运行的任务会被中断，请提前保存重要内容。
- 部分增强能力依赖当前 Codex 版本和当前线路支持情况，遇到不兼容时请以 Codey 控制台提示为准。
- mac arm版本因无签名原因会报损坏，运行`xattr -dr com.apple.quarantine /Applications/Codey.app`即可跳过
